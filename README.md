# qq_praise — QQ 名片点赞插件

插件向 bot 提供一个 `praise_user` 动作（LLM 可调用工具），由 bot **自主决定**是否给人点赞：有人 @ 求赞 / 求互赞 / 让 bot 点赞时，或 bot 自己想感谢、宠某个人时，会调用工具完成真实点赞，并用 bot 自己的口吻回应结果。是否给予、如何措辞完全由各自的人设决定，插件不预设任何固定话术，任何角色（傲娇、温柔、高冷……）都能直接使用。

插件不做关键词匹配、不做定时/事件自动触发、不在群里转述——"给不给、怎么说"完全交给模型。

## 工作机制

1. `praise_user` 作为 Action 注册进 chatter 的可用工具列表（仅 `default_chatter` 可用）
2. 模型在对话中自主决定是否调用：`target` 参数写对方 QQ 号，不记得时写昵称/群名片（插件会自动解析为 QQ 号）
3. 插件负责真实执行：黑名单/冷却检查 → 好友判断 → 按关系选择赞数 → 分批调用适配器 `send_like`
4. 调用结果（点了几个、失败原因、冷却中等）以文本返回给模型，工具说明要求它基于真实结果回应，不得假装没点

## 核心特性

- **自适应分批**：单次批量优先 20，被服务端拒（如 1001）自动降级 10 重试；50 赞 = 20+20+10
- **真人节奏**：分批之间随机等待 2~5 秒（可配），不一秒打满
- **24h 冷却**：同一人每天只点一次，冷却中调用会把"已点过"如实返回给模型
- **好友区分**：好友/非好友可分别设置赞数；非好友点赞需 bot 账号开通 SVIP
- **黑名单**：不点赞的 QQ 号列表
- **结果真实反馈**：成功/部分成功/失败/冷却/跳过原因全部如实告知模型，由它口述

## 已知 QQ 规则(实测)

- 单次 send_like 上限 20,超 50 会整单被拒(OIDB 1001)
- 好友每人每日点赞上限:非 SVIP 10 / SVIP 20,超出部分服务端拒绝后自动降级分批
- 每日点赞总量有上限,超出报 OIDB 20003,插件会停在真实值并告知模型
- 非好友点赞是 SVIP 特权,普通账号会被拒(插件只记日志)

## 配置

网页管理端 → 插件配置 → qq_praise,或直接编辑 `config/plugins/qq_praise/config.toml`。

| 配置项 | 默认 | 说明 |
|---|---|---|
| enabled | true | 是否启用插件 |
| stranger_like_enabled | true | 非好友点赞总开关 |
| friend_times | 20 | 好友每次赞数(SVIP 上限 20/人/天,非 SVIP 服务端按 10 截断) |
| stranger_times | 50 | 非好友每次赞数(≤50,需 SVIP) |
| like_interval_seconds | [2.0, 5.0] | 批间随机间隔秒 |
| cooldown_hours | 24 | 同一人冷却 |
| blacklist | [] | 不点赞的 QQ 号列表 |
